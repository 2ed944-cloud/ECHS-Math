# IB Mathematics: Applications and Interpretation SL Specification

## Active curriculum version

For ECHS cohorts assessed before 2029, use the IB Mathematics: applications and interpretation curriculum with first assessment 2021.

Do not silently mix the revised first-assessment-2029 course into current classes.

Build the future version separately.

## Course character

IB AI SL prioritizes mathematics in context, modeling, interpretation, and technology.

It must not feel like AP Calculus/Precalculus content with IB labels.

## Active SL assessment profile (first assessment 2021)

External assessment: 80%.

### Paper 1
- 90 minutes
- 80 marks
- technology required
- compulsory short-response questions
- 40% weighting

### Paper 2
- 90 minutes
- 80 marks
- technology required
- compulsory extended-response questions
- 40% weighting

### Internal assessment
Mathematical exploration:
- 20 marks
- 20% weighting

Revalidate the official guide before production changes.

## Content organization

Map lessons explicitly to the official syllabus content areas:

1. Number and algebra
2. Functions
3. Geometry and trigonometry
4. Statistics and probability
5. Calculus

Also capture:
- technology;
- modeling;
- interpretation;
- inquiry;
- communication;
- IA relevance where appropriate.

## Technology

GDC use is integral, not optional decoration.

A technology block should be able to provide device-specific steps for:
- TI-Nspire CX II;
- TI-84 Plus CE where relevant to ECHS practice;
- NumWorks if supported.

IB AI SL course logic should not require students to memorize long procedures better delegated to technology.

Students must understand what the output means.

## IB-style question design

Use authentic command terms and task progression.

Examples:
- state;
- write down;
- calculate;
- find;
- determine;
- show that;
- hence;
- interpret;
- explain;
- justify.

The command term must fit what the mark allocation expects.

## Multi-part structure

Question schema must support:
- parent scenario/data;
- parts (a), (b), (c);
- nested subparts;
- marks per part;
- dependencies (`hence`/use previous result);
- calculator requirement;
- answer precision;
- method/accuracy notes for teacher;
- command term.

## Context

IB AI context should be plausible and data-aware.

Strong contexts:
- finance;
- demographics;
- transport;
- environment;
- sports;
- health/public data;
- survey/statistics;
- networks/geometry;
- growth/decay;
- optimization/modeling.

Qatar contexts can be used where the mathematics remains natural.

## Statistics and regression

Create reusable workflows:
data
→ visualization
→ model/statistic
→ technology output
→ interpretation
→ limitations.

For regression:
- plot;
- equation;
- coefficient interpretation;
- correlation/fit when in syllabus;
- residual or model validity where appropriate;
- interpolation/extrapolation judgment.

## Numerical accuracy

Question metadata should define:
- exact answer accepted?;
- decimal places;
- significant figures;
- currency convention;
- bounds/precision expectations;
- follow-through policy for multi-part practice where appropriate.

Do not mark a mathematically valid rounded answer wrong because the engine has one string answer.

## GDC interaction

Where possible, provide:
- calculator goal;
- button path;
- screenshot/visual cue if licensed/created by ECHS;
- expected output;
- interpretation prompt;
- common error.

Do not overload conceptual slides with full button-by-button instructions if a collapsible calculator panel works better.

## IA support

The platform may support:
- question refinement;
- variable identification;
- data planning;
- mathematical-tool suggestions;
- reflection prompts;
- criterion-aligned self-checklists;
- citation/data-source organization.

Do not generate a student's final IA as their submitted work.

## Paper simulation

Create versioned Paper 1 / Paper 2 practice modes.

Support:
- marks;
- multi-part flow;
- formula booklet references if applicable;
- technology-required environment;
- timing;
- response review;
- teacher markscheme view;
- student markscheme release policy.

## Future 2029 version

Create a separate curriculum version only.

Provide migration tools:
- objective diff;
- lesson reuse candidates;
- question remapping candidates.

Do not overwrite current objective IDs.
