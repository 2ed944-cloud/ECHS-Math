# Guided demo playbook

Use `/demo/school/` for external conversations. It contains synthetic data.

## Rule
Never give a generic feature tour.

For each screen:
`buyer pain → feature evidence → operational outcome → confirmation question`

## 15-minute route

### 1. Learning architecture — 90 sec
Show the Learn → Practise → Recover → Master pathway.
Question:
“Is this connected workflow closer to what you want than the separate tools you use today?”

### 2. Student journey — 3 min
Show:
- today’s mission;
- mastery;
- adaptive/focused practice;
- review queue;
- assignments;
- knowledge map.

Tie to:
clarity, consistency, recovery.

### 3. Teacher command center — 4 min
Show:
- class readiness;
- mastery;
- students needing support;
- priority interventions;
- assignments;
- skill analysis.

Tie to:
earlier intervention and less manual hunting for evidence.

### 4. Practice + test creation — 3 min
Show route selection, adaptive/focused modes, timed test controls.
Tie to:
teacher workflow and targeted learning.

### 5. Family + administration — 2 min
Show family progress story and school-managed roles.
Tie to:
parent clarity and institutional control.

### 6. Close demo — 90 sec
Ask:
“Which part would create the most value in your school?”
Then:
“What would stop you from moving forward if the commercial and technical requirements fit?”

## Buyer-specific shortcuts

Head of Math:
Teacher → Practice → Test → Student.

Principal:
Architecture → Teacher evidence → Family → Admin.

IT:
Admin → architecture/security discussion → implementation requirements. Keep academic demo short.

Procurement:
No full demo unless requested. Confirm scope and commercial process.

## Demo boundaries
- Synthetic data only.
- Never show production credentials.
- Never open restricted “Official AP” material.
- Do not claim a function based only on a mock screen; distinguish demo representation from repository-backed capability.
